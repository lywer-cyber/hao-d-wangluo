# §1 项目是什么

| 项 | 值 |
|---|---|
| 任务 | **数字全息重建强度图**的单图超分 LR×4 → HR |
| 输入 | LR 强度图，3 通道 BMP，8 bit，256×320 |
| 输出 | HR 强度图，3 通道，4× 尺寸，1024×1280 |
| 数据 | 5000 对（HR/LR4），**预生成**，禁止训练时在线退化 |
| 评价 | PSNR / SSIM / LPIPS / RMSE / MAE（RGB、[0,1]、crop_border=4） |
| 数据划分 | train 501–4500（4000）／val 1–250+4751–5000（500）／test 251–500+4501–4750（500），三方零重叠 |
| 退化链 | 圆孔径衍射低通 → 抗混叠高斯 → 面积平均×4 → 乘性散斑 → 泊松散粒+读出噪声 → 8bit |
| 退化参数 | 训练集逐样本抖动；**val 与 test 用同一组固定值**（保证所有模型面对完全相同的退化） |
| 唯一自由变量 | **网络结构**（`network_name` / `network_type` / `network_params`） |

**核心物理前提**：退化被 `r̂ = 1`（LR 的 Nyquist，`f_LR = 1/(2·scale) = 0.125` cycles/px）
切成两个性质不同的子问题 —— **带内（r̂<1）= 复原**（信息还在）、**带外（r̂>1）= 外推**（信息已丢）。
方法设计（HoloRestormer v3）就是围绕这条线做的。

## 6.1 B 机训练代码缺 GFL+HF 损失（**最严重**）

**现象**：B 的日志从头到尾没有 `l_gfl` / `l_hf`，而 A 有。

**根因**：`holo_project` 这份代码里 **GFL/HF 从未实现**。
`basicsr/models/losses/losses.py` 只有 L1/MSE/PSNR/Charbonnier；
`optimize_parameters` 只算 `l_pix = sum(self.cri_pix(...))`。

**证据**：全仓库 `grep -rn "gfl|GFL|hf_sigma|loss_hf" --include=*.py` 只命中
`run_holo_trials.py:276-280` —— 那是**生成 yml 的模板字符串**，把 `loss_gfl_weight: 0.1`
抄进配置却没有任何实现。**配置里那两行是死字段。**

**影响**：旧 SwinIR run 实际是**纯 L1**，与 A（L1+GFL+HF）不可比 ——
违反协议 §9.6「禁止每个模型使用不同损失」、§14.1 `same_loss`、§20-2。对比前提不成立。

**改法**（只改代码，配置文件一个字段没动）：
`holo_project/restormer/basicsr/models/image_restoration_model.py`
1. `__init__` 读 `loss_l1_weight / loss_gfl_weight / loss_hf_weight / gfl_ramp_iterations / gfl_radius_ref / hf_sigma_px / ema_warmup_iters`
2. 新增 `_frequency_loss`（GFL，协议 §9.3）与 `_high_frequency_loss`（HF，§9.4），照 A 的实现逐字搬
3. 损失从 fp16 autocast 移出到 `autocast(enabled=False)` 的 fp32 段
4. **顺带补了 EMA warmup 校正** `d = decay·(1−exp(−step/2000))`（协议 §7.4，原来也缺）

**验证**：合成数据 `(2,3,64,64)→(2,3,256,256)` 冒烟，
`l_total = 1.0·l_pix + 0.1·l_gfl + 0.2·l_hf` 相对误差 **5.3e-08**；4 次 micro-step 触发 1 次 update（accum=4）。

**备份**：`image_restoration_model.py.bak_before_gfl_hf`
**记录**：`holo_project/experiments/NOTE_gfl_hf_rerun_20261013.md`

> ⚠️ **两份代码的损失实现位置不同**：A 在 `image_restoration_model.py` 里，**不在 `losses/` 目录**。

## 6.2 评估脚本两个真 bug（已修并逐位验证）

### ① 用的不是 EMA 权重

**根因**：协议 §17 明确 `net_g_ema.pth` 是**正式**权重、`net_g_raw.pth` 只是**审计**用。
best checkpoint 里两份都存了（209,410,547 B = 2× 104.7 MB），但脚本只读 raw：

```python
model.load_state_dict(state.get("params", state), strict=True)   # ← 旧
```

而训练的 validation 用的是 `net_g_ema`（`image_restoration_model.py:327-330`）。

**影响**：**选点用 EMA、报数用 raw** —— 报出来的不是被选中的那个模型。
实测差 0.014 dB（raw 31.2160 vs EMA 31.2302）。

### ② 评不了 SwinIR

**根因**：脚本写死
`from basicsr.models.archs.holo_restormer_arch import HoloRestormer`，
`model = HoloRestormer(**net_opt)`。B 的 run 是 `HoloSwinIR` →
硬建一个 HoloRestormer 再 `strict=True` 加载 SwinIR 权重 → **直接报错**。
**对比表里 SwinIR 那一列根本生成不出来。**

**改法**：
- 优先 `params_ema`，回退 `params`
- 改用 `basicsr.models.archs.define_network`（按 `network_g.type` 动态解析类名，与训练代码同一机制）
- 打印一行 `[eval] 网络类型=... 载入权重=...` 便于事后核对

**验证**：修完重跑独立评估得到 **PSNR 31.23019984112509 / SSIM 0.9067392385380516**，
与训练日志 val@35000 的 **31.2302 / 0.9067** **逐位吻合** →
**"训练 → EMA 选点 → 独立评估"整条链证明一致。**

**备份**：两个文件下都有 `evaluate_holo.py.bak_before_fix`

## 6.3 评估（浮点）与出图（8bit BMP）的口径冲突

**不是 bug，是固有差异。**

`evaluate_holo.py` 的 PSNR/SSIM 算在**浮点** SR 上（`model(inp).clamp(0,1)`）；
BMP 母版是 `np.clip(sr*255).astype(uint8)` 之后的 **8 bit 量化**结果。
`export_per_sample_metrics.py` 从 BMP 复算再和 `metrics.json` 比，容差 **1e-6**，
而 8 bit 量化带来的 PSNR 偏差约 **0.007 dB** → **必然超差、脚本报错退出**。

**处置**：**口径定死 —— 论文数字用 `metrics.json`（浮点），出图用 BMP**；出图链路加 `--no-check`。

## 6.4 A 机基线的重建头不是官方 Restormer（**已改，重跑中**）

**现象**：v7 的 Restormer 基线比 v6 的原版低 1.4~1.9 dB。

**根因**：重建头不同。

| | 旧 run（v7 基线） | 官方 Restormer SR（v6） |
|---|---|---|
| output | `Conv2d(96 → 3)` | `Conv2d(96 → 3×4²=48)` |
| 上采样 | `SRUpsample`：Conv(3,12)+PS2 → Conv(3,12)+PS2 | `PixelShuffle(4)` |
| 参数量 | 26,127,292 | **26,165,524** |

**证据**：`26,127,292 + 38,232 = 26,165,524`，**精确等于 v6** →
说明两个版本的差别**只在重建头**。
实测影响：iter 5000 时 28.83/0.8370（旧）vs 30.22/0.9006（新）→ **+1.39 dB**。

**性质**：**不是崩溃 bug，是身份错位** —— 代码里 docstring 原文
"Frozen-v7 baseline: Restormer-shaped ×4 SR **without v3 redesign flags**"，
是有人故意换的头；但不能叫"官方 Restormer"。

**改法**：`holo_restormer_arch.py` 加开关 `use_staged_head`，**默认 `True` 保持不变**
（旧 run 的检查点仍可复现、可评估），新 run 显式传 `false`。

# §7 论文口径：现在能写什么、不能写什么

**依据源码核对，不依据设计文档。**

## 7.1 两个类

```python
class HoloRestormerV3(nn.Module):        # 研究版：8 个开关【默认全开】→ 88.7M 参数
class HoloRestormer(HoloRestormerV3):    # 基线版：8 个开关【强制全关】
```

`HoloRestormer` 的 docstring 原文：
> Frozen-v7 baseline: Restormer-shaped ×4 SR **without v3 redesign flags**.
> …the v7 baseline config uses this class and **must not silently enable** homomorphic, band,
> directional, skip-gate, or unroll modules.

## 7.2 基线版与官方 Restormer 的关系（**逐项核对过**）

**相同**：
- `HoloStem(use_homomorphic=False)` → 返回官方 `OverlapPatchEmbed(...).proj`，**同一个 conv**
- `HoloAttention(use_nonlinear_v=False)` → `return super().forward(x)`，**就是官方 MDTA**
- `HoloGDFN(use_dirconv=False)` → `dirconv=Identity`，**就是官方 FeedForward**
- `HoloBlock` 开关全关时走快速路径，代码注释原文
  "*This branch deliberately mirrors TransformerBlock's two expressions*"：
  ```python
  x = x + self.attn(self.norm1(x))
  x = x + self.ffn(self.norm2(x))
  ```

**关键**：`HoloBandSplit` 只有 `masks()` / `band_energy()` 两个方法，
**在 forward 里没有任何调用点** —— 在基线版里是纯装饰，不参与计算。

## 7.3 能不能写

| 想写的东西 | 能不能 |
|---|---|
| "本文方法 = 条纹尺度 × 频带、带内复原/带外外推" | ❌ **现在不能** —— 那些模块在已训练的网络里全是关的 |
| "基线：官方 Restormer" | ✅ 成立（`..._stockhead_...`，26,165,524） |
| "基线：Restormer + 两级重建头（我们的变体）" | ✅ 也行，指旧 run；但不能叫"官方 Restormer" |
| "HoloBandSplit 按物理截止频率分带" | ❌ 基线版里不参与计算 |
| "本文做了 D4 自集成" | ❌ 代码里没实现 |

# §8 战略：基线太强怎么发文章

**核心思路：不需要从外面打败它。**

你的方法就是 Restormer 叠模块 —— 比的是"加了模块的自己 vs 没加的自己"，这是**消融**，不是打擂台。
而且 **基线强是好事**：弱基线才是被拒的理由。

## 8.1 真正要解决的是参数量，不是精度

全开 **88.7 M** 打赢基线 **26 M**，没人会认（差 3.4 倍；对 SwinIR 差 25 倍）。

**出路是挑参数中性的模块** —— 这样"涨了就是物理先验的功劳，不是容量堆的"，审稿人无法反驳：

| 模块 | 参数量性质 |
|---|---|
| `use_nonlinear_v` | **加 0 参数**（一个 tanh） |
| `HoloStem` 双域 | **参数中性**（dim 拆两半） |
| `DirConv` 替换 GDFN 的 `dwconv` | 可做到**参数中性**（替换而非新增） |
| P3 的物理展开数据保真项 | **零可学参数**（`D_det` + 伴随，设计文档说这是最强创新点） |

> **同等参数下 +0.1~0.2 dB，比多 3 倍参数下 +0.5 dB 值钱得多。**

## 8.2 先做便宜的验证，别赌大 run

每项改造单独跑 **5k iter A/B ≈ 1.5 小时**，8 项约 **15 小时** 就能知道哪些真有用。
**别一上来就赌 17 小时的全开 run。**

门禁判据（设计文档 §4.2，**两条都要满足**）：
```
① Δ val PSNR ≥ +0.05 dB
② 训练 l_pix 不劣化（同窗口均值相对差 ≤ +2%）   ← ② 是 band 的教训
不通过 → 回退并如实记录，禁止调参救场
```

## 8.3 如果 PSNR 就是涨不动，光学期刊还有别的出口

- **退化参数鲁棒性** —— HoloPASWIN 在 ±1mm 处掉到 10 dB 以下，是领域公认最大失败点。
  你的带内/带外解耦天然是冲这个去的，**"OOD 更稳"本身就是可发表的主张**
- 少样本（本域数据比自然图 SR 少 1–2 个数量级）
- 等参数下的效率 / 推理时间
- LPIPS / 视觉质量（散斑重，PSNR 会饱和且与视觉背离）

## 8.4 诚实提示的风险

设计文档里**已经有过一次模块失败记录**（`band`：训练 l_pix 高 5–10%、val 低 0.6 dB = 欠拟合）。
所以"加了模块一定有用"**没有保证**，必须先测。

# §11 红线

1. 只用**验证集**选 checkpoint；测试集不参与任何选择。
2. 除 `network_name` / `network_type` / `network_params` 外不改配置。
3. **绝不动 `holo_degrade.py` 里任何 `rng` 的调用顺序**（LR 图会变，全部实验作废）。
4. 不用预训练权重；不加梯度裁剪；不给单个模型单独调 lr/betas。
5. 新模块的 **FFT 与降采样必须 fp32**（`autocast(enabled=False)`），fp16 FFT 精度不足会让训练不稳。
6. `DualGate` 门控方向：C-Map（全局池化）调 attention、S-Map（1×1 conv）调 freq。写反了会莫名变差。
7. 数据保真项里**不放**散斑/泊松/量化等随机项（会引入噪声梯度）。
8. **两条 run 的损失必须一致** —— 这是今天花最大代价修的（§6.1），别再让它们不一样。
9. **并联，不替换**原模块（`band` 的教训，§5.1）。

# §12 本机环境踩坑（**这台机器特有，务必知道**）

| 现象 | 应对 |
|---|---|
| **本机传文件会坏**：`tar` 会改内容、`sha256sum` 会撒谎（两边都坏却哈希一致） | 只用 `python3 hashlib` 核验 |
| **`ssh host "cat > f" < local` 会多喂 4096 字节乱码**（2312 B 的文件到远端变 6408 B） | 一律用**管道**：`cat local \| ssh host "cat > f"`，传完核哈希 |
| 长命令行参数（如一大串 base64）会被改坏 | 别用；要传文件按上面走 |
| **ssh 会间歇性 `Permission denied`**（密码正确，几秒后同一命令又通） | 所有远程操作**带重试** |
| 本机 `grep` 读某些文件会**返回空**（`fighelpers.py` 等） | 用 `python3` 读文件 / 搜代码，别信 grep |
| 对比字节数时别把 ssh 的 `Warning:` 串当成字节数 | `\| tr -dc 0-9` 洗净 |
| 非交互式 ssh 里 `python` 不在 PATH | 用全路径 `/root/miniconda3/bin/python` |

# §14 命名对照

| 名字 | 含义 |
|---|---|
| `HoloRestormer` | 基线版类：Restormer 体 + 8 开关全关 + 官方头（26.1 M） |
| `HoloRestormerV3` | 研究版类：8 开关全开（**88.7 M**）—— **方法本体** |
| `use_staged_head` | `True`（默认）= 两级 3 通道像素重排；`False` = 官方 `Conv(96→48)+PixelShuffle(4)` |
| `use_homomorphic` | P1 可学强度 Box-Cox 双域前端（`HoloStem`） |
| `use_restore_branch` / `use_extrap_branch` | P2 带内复原 / 带外外推支路（`FSASBranch` + `HoloBandSplit.masks`） |
| `use_dirconv` | 方向性带通（`DirConv`，`n_orient=6`） |
| `use_multiscale` | 多尺度深度卷积（`MultiScaleDW`，对应散斑相关长度 3–6 px） |
| `use_nonlinear_v` | MDTA 的 value 通路加 tanh（**0 参数**） |
| `use_skip_gate` | skip 按带能量门控（`BandGatedSkip` ×3） |
| `use_unroll` / `unroll_K` | P3 HQS 物理一致性展开（`HoloUnroll` + `HoloForwardDet`），**默认关** |
| GFL / HF | 引导频域损失（§9.3）/ 带外高频加权 L1（§9.4） |
| `f_LR` | LR 的 Nyquist = `1/(2·scale)` = 0.125 cycles/px，带内/带外的分界 |
| `r̂` | 归一化频率 = `r / f_LR`；`r̂ = 1` 就是那条物理边界 |
