# S5 结果：HoloForwardDet 数值一致性校验（2026-10-14）

脚本：`tests/s5_forwarddet_consistency.py`（sha256 32aaf8aa39ce553d…）
参照物：`pipeline/scripts/holo_degrade.py` 的确定性三步
（`fft_lowpass` 圆形孔径 + `gaussian_blur` + `cv2.INTER_AREA` 面积平均）
样本：`HR/263.bmp`，转单通道，scale=4，aa_sigma=0.5

## 结论：协议门槛 3 通过

| 检验 | 判据 | 实测 | 结果 |
|---|---|---|---|
| forward 与 numpy 生成器逐像素 MSE | < 1e-4 | **8.42e-06**（默认 cutoff=1.0） | 通过 |
| 同上，改用 cutoff=0.25 | < 1e-4 | 2.53e-06 | 通过 |
| 伴随性 \|&lt;D(x),y&gt; − &lt;x,Dᵀ(y)&gt;\| | < 1e-3 | **2.44e-04**（rel 1.9e-07） | 通过 |
| 尺寸 | forward(HR)→LR；adjoint(LR)→HR | (256,320)→(64,80)；(64,80)→(256,320) | 通过 |

伴随性成立的原因：传输函数是实对称的，所以低通算子自伴（Lᵀ = L），
而 `_lanczos_adjoint` 是 `_lanczos_downsample` 的精确转置 → `adjoint` 确实是 `forward` 的转置。

## 隐患（未改，需决策）：默认 cutoff=1.0 时孔径不起作用

`HoloForwardDet._mask` 的判据是 `sqrt((2fy)²+(2fx)²) <= cutoff`，即 **`2r <= cutoff`**。
- 传默认 `cutoff=1.0` → 等效截止 `r <= 0.5 cycles/px` = **HR 网格的整个非混叠频带**，
  等于**没有孔径低通**；
- 生成器的截止是 `diffraction_cutoff/(2·scale) = 1.0/8 = 0.125 cycles/px`；
- 要对齐生成器，应传 **`cutoff = 2 × 0.125 = 0.25`**。

实测印证：cutoff 从 1.0 换成 0.25，MSE 8.42e-06 → 2.53e-06（降 3.3 倍），
max|Δ| 4.70e-02 → 2.53e-02（降 1.9 倍）。

**影响**：`HoloUnroll.__init__` 里写的是 `HoloForwardDet(scale=scale)`，
用的是默认 `cutoff=1.0` → **P3 的一致性项现在用的算子和生成数据的算子是两回事**，
频带 0.125~0.5 本来被砍掉、现在却被保留（并会在降采样时混叠）。

## 另一个观察

即便取对齐的 cutoff=0.25，max|Δ| 仍有 **2.53e-02（约 6 个灰阶）**，
MSE 达标但最坏点不小。差异来源：FFT 是循环边界，生成器的 `cv2.GaussianBlur`
用 `BORDER_REFLECT`。**论文里不宜宣称二者"完全一致"，宜说"逐像素 MSE 量级 1e-6"。**

## 建议
1. 把 `HoloUnroll` 里的 `HoloForwardDet(scale=scale)` 改成显式 `cutoff=0.25`
   （或在 `HoloForwardDet` 里把外部 cutoff 的语义改成"以 LR Nyquist 为单位"）；
2. 改后重跑本脚本确认 MSE 不劣化；
3. 这属于 P3 的实现修正，**不改动 holo_degrade.py 的任何 rng 调用顺序**（红线 3）。
